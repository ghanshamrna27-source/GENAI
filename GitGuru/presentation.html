Section 1

Problem Statement

The Version Control Crisis & The Critical Flaws of Generic LLMs

❌ 1. Developer Pain & Code Loss
  • Over 40% of Junior Devs Experience Code Loss: Destructive commands like git reset --hard, corrupt merge conflict resolutions, and detached HEAD states cause irreversible data loss.
  • Commit & Branch Paralysis: Developers fear experimenting with branches, stashing, and rebasing because terminal errors are intimidating and hard to undo.
  • Lack of Visual Context: Git is a directed acyclic graph (DAG), but terminal commands provide no visual feedback on branch topology before execution.
⚠️ 2. Why Generic LLMs Fail at Git
  • Dangerous Unwarned Commands: Standard chatbots casually recommend destructive commands like git push --force or git clean -fd without repository awareness or confirmation.
  • Hallucinated Flags: LLMs routinely invent non-existent CLI flags and invalid syntax.
  • No Source Verification: Generic AI provides ungrounded answers with zero verifiable documentation citations.
  • Impossible Data Claims: Standard LLMs fail to say "I don't know" on impossible recovery scenarios (e.g. recovering code from zeroed hard drives without remotes).
Section 2

Technologies Used

Modern Multi-Tier Stack Built for Performance, Grounding, and Safety

⚙️ Backend & Agents
  • FastAPI: High-performance async ASGI web framework.
  • LangGraph: Stateful agent graphs with MemorySaver checkpointer.
  • LangChain Core: Tool binding & execution dispatcher.
  • Pydantic v2: Strict request/response validation with 1,000-char limits.
  • Python 3.11 / 3.14: Type-annotated, modern modular codebase.
🔍 Retrieval & Multi-LLMs
  • Persistent ChromaDB: Chunked vector storage (gitguru_chunks).
  • ONNX all-MiniLM-L6-v2: 384-dimensional dense semantic embeddings.
  • scikit-learn TF-IDF: Lexical search with Cosine Similarity keyword ranking.
  • Google Gemini (3.8 Flash): Primary reasoning model with dynamic failover.
  • Groq Cloud (GPT-OSS 120B): Ultra-fast secondary LLM provider.
🚀 UI, Security & DevOps
  • Streamlit: Interactive web UI with feedback loops and command simulation.
  • Mermaid.js: Real-time visual branch DAG graph renderer.
  • In-Memory LRU Cache: High-speed TTL cache (99.4% latency drop).
  • Prompt Shield: Pre-inference regex injection defense.
  • Docker & GitHub Actions: Multi-stage containers, CI/CD, and 33 Pytest tests.
Section 3

System Requirements

Functional & Non-Functional Engineering Constraints

📋 Functional Requirements (FR)
  • FR-1 (Grounded RAG Pipeline): Retrieve relevant documentation chunks and synthesize responses with verifiable citations ([Title, Page X]).
  • FR-2 (Strict Anti-Hallucination Guardrail): Must strictly return "I don't know based on the provided documentation" on impossible scenarios (e.g. Q6 formatted disk recovery).
  • FR-3 (Human-in-the-Loop Safety Gate): Autonomous agent must intercept destructive Git actions (reset --hard, push -f) and pause with pending_approval until confirmed.
  • FR-4 (Multi-Turn Conversational Memory): Persist conversation state across turns using session thread IDs (thread_id).
  • FR-5 (Interactive Branch Simulator): Simulate and visually graph Git topology in Mermaid before commands touch disk.
⚡ Non-Functional Requirements (NFR)
  • NFR-1 (Sub-5ms Latency): In-memory LRU response cache with TTL must serve warm hits in <5ms (benchmarked at 2.15ms).
  • NFR-2 (Token & Cost Efficiency): Cache hits must consume 0 LLM tokens, cutting overall production API costs by >60%.
  • NFR-3 (Input Security Shield): Enforce strict character limits (2–1,000 chars), null-byte stripping, and prompt injection defense.
  • NFR-4 (Production Observability): Measure per-request latency via middleware, inject X-Process-Time-Ms, and expose live metrics at GET /metrics.
  • NFR-5 (Automated Quality Gate): Maintain 100% test pass rate across 30+ Pytest tests with automated CI/CD verification.

Explaining the Endpoints in app/main.py

REST API Design for Search, RAG Synthesis, Multi-Turn Agents, and Telemetry

Endpoint Category Functionality & Execution Pipeline Response Model
GET /health Diagnostics Public health monitor reporting API status, environment health, and knowledge base record count. HealthResponse
GET /records Knowledge Base Lists all Git cheat-sheet command records with optional limit query parameter. List[RecordSchema]
GET /search Lexical Search TF-IDF Cosine Similarity search over cheat-sheet command records with keyword ranking. List[RecordSchema]
GET /search/semantic Vector Search Dense vector search querying ChromaDB; returns chunk text, source URL, page, and similarity score. List[SemanticResult]
POST /chat Conversational LLM Multi-turn chat. Evaluates Prompt Shield → In-Memory Cache → Gemini/Groq LLM call → Token estimation. ChatResponse
POST /ask Grounded RAG Flagship RAG endpoint. Retrieves chunks → checks Q6 refusal guardrail → synthesizes grounded response with citations. AskResponse
POST /agent Autonomous Agent LangGraph agent executor. Tracks thread memory and intercepts destructive operations with pending_approval. AgentResponse
GET /metrics Observability Exposes production metrics: latency (P50/P95), token consumption, cache hit rate, and cost savings. TelemetryJSON
